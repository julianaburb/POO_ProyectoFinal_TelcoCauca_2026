Descripción del proyecto:

TelcoCauca es el proyecto integrador que desarrollamos para la materia de Programación Orientada a Objetos en C++. La idea es simular, de una forma sencilla, cómo funcionaría el sistema de monitoreo de una empresa de telecomunicaciones aquí en el Cauca: hay torres con antenas, técnicos encargados de ellas, nodos de red que a la vez funcionan como sensores, varios tipos de dispositivos de comunicación y un servidor central que recibe los datos que le envían. Lo fuimos construyendo por módulos durante el semestre, siguiendo la guía del curso, y al final lo juntamos todo en un solo programa que se ejecuta de corrido y muestra la salida separada por partes.

En la primera parte modelamos la infraestructura física a partir del diagrama UML. Cada antena tiene un técnico responsable (asociación 1 a 1) y una torre guarda varias antenas en un vector de punteros (asociación 1 a N), así la torre puede mostrar un reporte de lo que tiene instalado.

La segunda parte trabaja la herencia múltiple. La clase NodoRedInteligente hereda al mismo tiempo de DispositivoRed y de SensorIot, porque un nodo de este tipo tiene IP y dirección MAC como cualquier equipo de red, pero además toma lecturas como un sensor. Aquí también sobrecargamos el operador + para sumar la carga de procesamiento de dos nodos, y el operador << como función amiga para poder imprimirlos directamente con cout. Si al crear un nodo la IP viene vacía o la lectura se sale del rango permitido, el constructor lanza una ExcepcionNodoRed, que es una excepción propia que hereda de std::runtime_error. En el main provocamos esos dos errores a propósito para comprobar que se capturan bien.

En la tercera parte entra el polimorfismo. ITransmisible es una interfaz pura con el método serializar(), y DispositivoComunicacion es una clase abstracta que la implementa y deja transmitir() como método virtual puro; su destructor es virtual para que al hacer delete desde un puntero a la clase base también se llame al destructor de la hija. De ella heredan RouterWiFi, GatewayLoRa y SwitchFibra. Todos se guardan en un std::vector<DispositivoComunicacion*> (con punteros y no con objetos, para evitar el slicing) y cada dispositivo se supervisa en su propio hilo con std::thread, por medio de la clase SupervisorRed. Como varios hilos escriben en la consola y modifican el mismo contador de transmisiones exitosas, esa sección crítica está protegida con un std::mutex y std::lock_guard, que por el patrón RAII libera el mutex automáticamente aunque se lance una excepción. Dentro del vector metimos a propósito un router sin IP y un puntero nulo, para mostrar que cada hilo atrapa su propio error sin que el programa se caiga.

La cuarta parte es la agenda de eventos de ingeniería 2027 (NVIDIA GTC, ITW Global y Telco Transformation LATAM), que se procesa en un hilo independiente. Cada evento valida que de verdad sea del 2027, y los mensajes se imprimen con una función de registro protegida por mutex para que no se mezclen con lo que escriben los otros hilos.

La última parte es la de red, y fue la que más trabajo nos dio. Implementamos un ServidorCentral TCP que sigue la secuencia socket, bind, listen y accept, y que crea un hilo para cada cliente que se conecta (hasta tres). Los clientes mandan una trama de texto con el formato TIPO|ID|IP|VALOR; el servidor la separa en sus campos, la muestra y responde con un ACK. Después de que el servidor se apaga intentamos conectar otro cliente, y ese fallo se captura como runtime_error. Para la telemetría usamos UDP: los datos del nodo se empaquetan en la estructura binaria TramaSensor con #pragma pack(1), para que mida exactamente 40 bytes sin relleno, y se envían con sendto. El receptor los recibe con recvfrom y tiene un timeout de 3 segundos configurado con setsockopt, entonces si no le llega nada lanza una ExcepcionRedUDP en lugar de quedarse bloqueado.

Al final el programa recorre los vectores dinámicos, hace delete de cada elemento y deja los punteros en nullptr, para no dejar fugas de memoria ni punteros colgantes. El código compila tanto en Windows (Winsock) como en Linux (sockets POSIX). El trabajo lo realizamos repartiendo tareas entre nosotros, haciendo uso de VS Code con el repositorio de GitHub.
